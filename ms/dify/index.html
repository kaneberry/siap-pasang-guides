Cara pasang Dify guna Docker Compose

1. Apa itu Dify?

Dify ialah platform untuk bina aplikasi AI — chatbot, aliran kerja (workflow/chatflow), ejen AI dan pangkalan pengetahuan (RAG) — melalui antara muka visual. Anda sambung model daripada penyedia seperti OpenAI, Anthropic, Gemini atau Ollama, kemudian terbitkan aplikasi sebagai laman web atau API.

Sesuai untuk: pasukan kecil dan PKS yang mahu bina chatbot dalaman atau automasi AI berdasarkan dokumen sendiri, serta pembangun yang mahu prototaip aplikasi AI dengan cepat.

  • Repo rasmi: https://github.com/langgenius/dify
  • Dokumentasi rasmi: https://docs.dify.ai/en/self-host/deploy/quick-start/docker-compose

💡 Jujur dulu: Dify jauh lebih berat daripada n8n atau Open WebUI. Satu pemasangan menjalankan lebih 15 bekas (API, worker, pangkalan data, Redis, pangkalan data vektor, sandbox dan lain-lain). Ia juga tiada model sendiri — anda perlukan kunci API penyedia model atau Ollama. Jika anda tidak mahu urus server, Dify Cloud ialah pilihan lebih mudah: https://dify.ai/pricing

2. Prasyarat

  • VPS dengan Ubuntu 24.04 atau 22.04 (64-bit) dan akses sudo.
  • Minimum rasmi: CPU ≥ 2 teras, RAM ≥ 4 GiB.
  • Docker 19.03+ dan Docker Compose 2.24.0+ (dipasang dalam Seksyen 4).
  • Alat git, curl dan jq (dipasang dalam Seksyen 5.1).
  • Asas SSH: boleh log masuk ssh user@IP_SERVER.
  • Kunci API penyedia model (contoh OpenAI) atau Ollama yang boleh dicapai dari server.
  • Port 80 dibuka di firewall penyedia VPS — atau guna terowong SSH (lihat Akses peribadi guna terowong SSH), yang lebih selamat.

4. Pasang Docker

Log masuk ke VPS, kemudian kemas kini sistem:

sudo apt update && sudo apt upgrade -y

Pasang Docker Engine + plugin Docker Compose guna skrip rasmi Docker:

curl -fsSL https://get.docker.com -o get-docker.sh
sudo sh get-docker.sh

Mahu cara manual (repo apt)? Ikut panduan rasmi: https://docs.docker.com/engine/install/ubuntu/

Semak pemasangan:

docker --version
docker compose version
sudo docker run hello-world

Pastikan docker compose version menunjukkan 2.24.0 atau lebih baharu — Dify tidak akan berjalan dengan versi lebih lama. Jika anda nampak mesej Hello from Docker!, Docker sudah sedia.

(Pilihan) Guna Docker tanpa sudo:

sudo usermod -aG docker ${USER}
exec sg docker newgrp
groups   # pastikan "docker" ada dalam senarai

5. Pasang Dify

5.1 Pasang git, curl dan jq

sudo apt install -y git curl jq

5.2 Muat turun (clone) Dify versi terkini

Arahan rasmi ini mencari tag keluaran terkini melalui API GitHub, kemudian clone versi itu:

git clone --branch "$(curl -s https://api.github.com/repos/langgenius/dify/releases/latest | jq -r .tag_name)" https://github.com/langgenius/dify.git

Mahu tahu versi apa yang akan dipasang dahulu?

curl -s https://api.github.com/repos/langgenius/dify/releases/latest | jq -r .tag_name

Ketika panduan ini ditulis (2 Nov 2026), output ialah 1.18.0.

📝 Ralat fatal: Remote branch null not found? Biasanya API GitHub mengehadkan permintaan tanpa log masuk, jadi jq pulangkan null. Clone dengan tag yang ditulis terus — semak nombor versi terkini di https://github.com/langgenius/dify/releases:

bash git clone --branch 1.18.0 https://github.com/langgenius/dify.git

5.3 Sediakan fail .env

cd dify/docker
cp .env.example .env

Semua tetapan permulaan penting berada dalam docker/.env.

5.4 Jana token sandbox ejen (wajib)

openssl rand -base64 32

Salin output, kemudian buka .env:

nano .env

Cari baris DIFY_AGENT_LOCAL_SANDBOX_AUTH_TOKEN= (guna Ctrl+W untuk cari) dan tampal output tadi:

DIFY_AGENT_LOCAL_SANDBOX_AUTH_TOKEN=tampal-output-openssl-di-sini

Simpan (Ctrl+O, Enter, Ctrl+X), kemudian kunci kebenaran fail:

chmod 600 .env

⚠️ Menurut docs rasmi, servis agent_backend dan sandboxnya tidak akan bermula tanpa token ini.

5.5 Hidupkan Dify

sudo docker compose up -d

Muat turun kali pertama ambil masa beberapa minit (banyak imej). Bekas yang dimulakan:

  • 7 servis teras: api, api_websocket, worker, worker_beat, web, plugin_daemon, agent_backend
  • 8 komponen sokongan: weaviate (pangkalan data vektor), db_postgres, redis, nginx, ssrf_proxy, agent_ssrf_proxy, sandbox, local_sandbox
  • 1 tugas sekali jalan: init_permissions — tetapkan kebenaran storan, kemudian keluar

Apa yang perlu tahu (ringkas):

  • nginx ialah pintu masuk tunggal — ia mendengar di port 80 server anda dan hantar trafik ke web dan api.
  • Data (pangkalan data, fail muat naik, vektor) disimpan dalam folder dify/docker/volumes/. Jangan padam folder ini.
  • Untuk hentikan semua bekas: sudo docker compose down (data kekal).

6. Nota .env dan keselamatan

Pemboleh ubah Fungsi Nilai selamat / contoh
DIFY_AGENT_LOCAL_SANDBOX_AUTH_TOKEN Token antara ejen dan sandbox tempatan (wajib) Output openssl rand -base64 32
SECRET_KEY Kunci tandatangan sesi Biarkan kosong — Dify jana kunci kekal secara automatik dalam folder storan
EXPOSE_NGINX_PORT Port HTTP di server 80 (lalai). Tukar jika port 80 sudah dipakai
EXPOSE_NGINX_SSL_PORT Port HTTPS di server 443 (lalai)

Peraturan keselamatan:

  • Jangan commit .env ke GitHub. chmod 600 .env supaya hanya pemilik boleh baca.
  • Dalam .env.example versi 1.18.0, DIFY_AGENT_SERVER_SECRET_KEY datang dengan nilai lalai pembangunan dan komen dalam fail itu meminta ia ditukar untuk production. Ikut arahan dalam komen tersebut.
  • Kunci API penyedia model yang anda masukkan dalam Dify disimpan dalam pangkalan data (dalam volumes/). Backup folder itu dan lindunginya. Kalau kunci API bocor, tukar (rotate) di penyedia asal dengan segera.
  • http://IP_SERVER ialah HTTP biasa (tidak disulitkan). Membuka port 80 ke internet tanpa HTTPS berisiko — kata laluan dan kunci API dihantar tanpa penyulitan. Guna terowong SSH untuk mula, dan sediakan HTTPS sebelum kongsi dengan orang lain (lihat Seksyen 9).
  • Port yang diterbitkan oleh Docker biasanya memintas peraturan ufw. Jangan anggap ufw sahaja melindungi port 80 — semak juga firewall di panel VPS.

7. Sahkan dan cipta akaun admin

sudo docker compose ps

✅ Setiap bekas patut berstatus Up atau healthy. Status Exited untuk init_permissions adalah normal (tugas sekali jalan).

Lihat log jika ada bekas yang restart berulang:

sudo docker compose logs -f api
sudo docker compose logs -f agent_backend

Buka pelayar ke halaman permulaan admin:

http://IP_SERVER/install

✅ Skrin dijangka: borang untuk sediakan akaun admin (emel, nama, kata laluan). Selepas selesai, log masuk di http://IP_SERVER.

⚠️ Lengkapkan langkah /install segera selepas Dify hidup. Selagi akaun admin belum dicipta, sesiapa yang boleh capai server anda boleh membukanya dahulu. Terowong SSH (di bawah) mengelakkan risiko ini.

Langkah seterusnya dalam Dify: buka Settings › Model Provider, pasang plugin penyedia model anda, dan masukkan kunci API.

Akses peribadi guna terowong SSH

Tidak mahu buka port 80 ke internet? Dalam docker/.env, ikat port nginx kepada 127.0.0.1 sahaja:

EXPOSE_NGINX_PORT=127.0.0.1:80
EXPOSE_NGINX_SSL_PORT=127.0.0.1:443

Kemudian mulakan semula:

sudo docker compose down
sudo docker compose up -d

Dari komputer anda (terminal baharu):

ssh -L 8080:localhost:80 user@IP_SERVER

Buka http://localhost:8080/install di komputer anda. Hanya anda (melalui SSH) boleh capai Dify.

📝 Cara ikat ke 127.0.0.1 ini ialah tip kami (format port standard Docker Compose), bukan langkah dalam docs rasmi Dify. Jika ada ciri yang tidak berfungsi melalui terowong, kembalikan nilai asal dan guna HTTPS.

9. Seterusnya (pilihan)

HTTPS: jangan biarkan Dify terbuka di HTTP biasa untuk kegunaan pasukan. Dua pilihan:

  • Letak Dify di belakang reverse proxy anda sendiri (contoh Caddy/Traefik/Nginx) dengan sijil TLS, atau
  • Guna sokongan HTTPS terbina dalam nginx Dify — pemboleh ubah NGINX_HTTPS_ENABLED, NGINX_SSL_CERT_FILENAME serta bahagian Certbot Configuration (CERTBOT_EMAIL, CERTBOT_DOMAIN). Ikut docs rasmi: Dify Docs — Environment Variables.

Selepas HTTPS hidup, kemas kini pemboleh ubah URL (contoh CONSOLE_API_URL, CONSOLE_WEB_URL) supaya guna https://.

Ubah tetapan: edit docker/.env, kemudian:

sudo docker compose down
sudo docker compose up -d

Backup sebelum kemas kini (wajib):

cd ~/dify/docker && sudo docker compose down
cd ~ && sudo cp -r dify "dify.bak.$(date +%Y%m%d%H%M%S)"

Arahan cp ialah cadangan docs rasmi (FAQ). Kami hentikan bekas dahulu supaya salinan pangkalan data konsisten. Simpan salinan backup di luar VPS juga.

Kemas kini Dify:

  • Langkah naik taraf boleh berbeza antara versi. Baca nota keluaran versi sasaran di https://github.com/langgenius/dify/releases dan ikut arahannya.
  • Selepas naik taraf, bandingkan .env.example baharu dengan .env anda untuk pemboleh ubah baharu atau berubah:
cd ~/dify/docker
diff .env.example .env
  • Jika anda pernah ubah docker-compose.yaml, guna semula perubahan anda pada fail baharu — jangan kekalkan fail lama, kerana versi baharu mungkin tambah servis yang Dify perlukan.
  • Kemudian tarik imej baharu dan hidupkan semula:
sudo docker compose pull
sudo docker compose up -d

Keselamatan asas: kemas kini Ubuntu secara berkala (sudo apt upgrade), guna kunci SSH (bukan kata laluan), dan jangan dedahkan port pangkalan data atau Redis ke internet.
