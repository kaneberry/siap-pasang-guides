Cara pasang Uptime Kuma guna Docker Compose

1. Apa itu Uptime Kuma?

Uptime Kuma ialah alat pemantau uptime self-hosted — alternatif kepada perkhidmatan seperti UptimeRobot yang berjalan di server anda sendiri. Ia menyemak laman web, API dan server anda secara berkala, kemudian hantar notifikasi (contoh Telegram, Discord, Slack, e-mel) apabila sesuatu tidak dapat dicapai.

Antara ciri yang disenaraikan dalam README rasmi:

  • Pantau HTTP(s), TCP, kata kunci HTTP(s), JSON Query, WebSocket, Ping, rekod DNS, Push, bekas Docker dan lain-lain
  • Notifikasi melalui Telegram, Discord, Gotify, Slack, Pushover, e-mel (SMTP) dan 90+ perkhidmatan lain
  • Selang semakan sehingga 20 saat
  • Status page berbilang (boleh dipetakan ke domain sendiri), maklumat sijil SSL, sokongan 2FA

Sesuai untuk: pemilik laman web, freelancer dan pasukan kecil yang mahu tahu dahulu apabila laman atau perkhidmatan mereka down — tanpa langganan bulanan.

  • Repo rasmi: https://github.com/louislam/uptime-kuma
  • Dokumentasi rasmi: https://uptime.kuma.pet/docs/How-to-Install/

💡 Tip penting: Untuk pemantauan yang bermakna, pasang Uptime Kuma pada server yang berbeza daripada laman/perkhidmatan yang dipantau. Jika kedua-duanya di VPS yang sama dan VPS itu down, Uptime Kuma juga down — dan tiada siapa yang hantar notifikasi.

2. Prasyarat

  • VPS dengan Ubuntu 24.04 atau 22.04 (64-bit) dan akses sudo.
  • Docker Engine dengan plugin Docker Compose — arahannya docker compose, bukan docker-compose (dipasang dalam Seksyen 4).
  • Cakera tempatan untuk folder data. Docs rasmi menyatakan sistem fail rangkaian seperti NFS tidak disokong (lihat Seksyen 6).
  • Alat curl dan asas SSH: boleh log masuk ssh user@IP_SERVER.
  • Port 3001 dibuka di firewall penyedia VPS — atau guna terowong SSH (lihat Akses peribadi guna terowong SSH), yang lebih selamat.

4. Pasang Docker

Log masuk ke VPS, kemudian kemas kini sistem:

sudo apt update && sudo apt upgrade -y

Pasang Docker Engine + plugin Docker Compose guna skrip rasmi Docker:

curl -fsSL https://get.docker.com -o get-docker.sh
sudo sh get-docker.sh

Mahu cara manual (repo apt)? Ikut panduan rasmi: https://docs.docker.com/engine/install/ubuntu/

Semak pemasangan:

docker --version
docker compose version
sudo docker run hello-world

Jika anda nampak mesej Hello from Docker! dan docker compose version memaparkan nombor versi, Docker sudah sedia.

(Pilihan) Guna Docker tanpa sudo:

sudo usermod -aG docker ${USER}
exec sg docker newgrp
groups   # pastikan "docker" ada dalam senarai

5. Pasang Uptime Kuma

5.1 Cipta folder projek dan muat turun compose.yaml

Arahan rasmi daripada README Uptime Kuma:

mkdir uptime-kuma
cd uptime-kuma
curl -o compose.yaml https://raw.githubusercontent.com/louislam/uptime-kuma/master/compose.yaml

Semak kandungan fail:

cat compose.yaml

Kandungan rasmi (ketika panduan ini ditulis, 3 Nov 2026):

services:
  uptime-kuma:
    image: louislam/uptime-kuma:2
    restart: unless-stopped
    volumes:
      - ./data:/app/data
    ports:
      # <Host Port>:<Container Port>
      - "3001:3001"

Maksud setiap baris (ringkas):

  • image: louislam/uptime-kuma:2 — tag :2 sentiasa ikut keluaran versi major 2 terkini. Ketika panduan ini ditulis, keluaran terkini ialah 2.5.9 (diterbitkan 31 Okt 2026).
  • ./data:/app/data — semua data (pangkalan data, tetapan, monitor) disimpan dalam folder data di sebelah compose.yaml. Jangan padam folder ini.
  • "3001:3001" — antara muka web pada port 3001.

5.2 Hidupkan Uptime Kuma

sudo docker compose up -d

Selepas imej dimuat turun, Uptime Kuma berjalan pada semua antara muka rangkaian — contoh http://IP_SERVER:3001.

Untuk hentikan: sudo docker compose down (data dalam ./data kekal).

6. Nota storan dan keselamatan

⚠️ NFS / sistem fail rangkaian tidak disokong. Docs rasmi menyatakan sistem fail perlu menyokong POSIX file lock untuk elak pangkalan data SQLite rosak. Petakan /app/data ke folder tempatan atau Docker volume — bukan NFS, SMB atau storan rangkaian lain.

Peraturan keselamatan:

  • http://IP_SERVER:3001 ialah HTTP biasa (tidak disulitkan). Membuka port 3001 ke internet tanpa HTTPS berisiko — kata laluan admin dan data monitor dihantar tanpa penyulitan. Guna terowong SSH untuk mula, dan sediakan reverse proxy + HTTPS sebelum akses dari internet (lihat Seksyen 10).
  • Port yang diterbitkan oleh Docker biasanya memintas peraturan ufw. Jangan anggap ufw sahaja melindungi port 3001 — semak juga firewall di panel VPS.
  • Aktifkan 2FA untuk akaun admin selepas log masuk (Settings › Security).

7. Sahkan dan cipta akaun admin

sudo docker compose ps

✅ Bekas uptime-kuma patut berstatus Up. Imej rasmi ada healthcheck terbina, jadi status mungkin bertukar kepada healthy selepas beberapa minit.

Lihat log jika bekas restart berulang:

sudo docker compose logs -f uptime-kuma

Buka pelayar ke:

http://IP_SERVER:3001

✅ Skrin dijangka (kali pertama):

  1. Pilih pangkalan data — Uptime Kuma 2 bertanya "Which database would you like to use?". Untuk persediaan kecil, pilih SQLite (antara muka menerangkannya sebagai recommended for small-scale deployments). Pilihan lain: Embedded MariaDB (sudah ada dalam imej Docker) atau MariaDB/MySQL luaran.
  2. Cipta akaun admin — isi nama pengguna dan kata laluan yang kuat.

⚠️ Cipta akaun admin segera selepas Uptime Kuma hidup. Selagi belum ada admin, sesiapa yang boleh capai port 3001 boleh menyediakannya dahulu. Terowong SSH (di bawah) mengelakkan risiko ini.

Akses peribadi guna terowong SSH

README rasmi menunjukkan cara hadkan akses kepada localhost sahaja dengan -p 127.0.0.1:3001:3001 (contoh docker run). Untuk Docker Compose, tukar baris port dalam compose.yaml dengan cara yang sama (tip kami, disesuaikan daripada contoh rasmi):

    ports:
      - "127.0.0.1:3001:3001"

Kemudian mulakan semula:

sudo docker compose down
sudo docker compose up -d

Dari komputer anda (terminal baharu):

ssh -L 3001:localhost:3001 user@IP_SERVER

Buka http://localhost:3001 di komputer anda. Hanya anda (melalui SSH) boleh capai Uptime Kuma. Tetapan ini juga sesuai jika anda letak reverse proxy di VPS yang sama.

8. Selepas pasang

  1. Tambah monitor pertama: klik Add New Monitor, pilih jenis (contoh HTTP(s)), isi nama mesra dan URL laman anda, kemudian Save.
  2. Sediakan notifikasi: Settings › Notifications › Setup Notification, pilih perkhidmatan (contoh Telegram atau e-mel SMTP) dan klik Test untuk pastikan mesej sampai. Kemudian aktifkan notifikasi itu pada monitor anda.
  3. (Pilihan) Status page: Status Pages › New Status Page untuk halaman status awam yang boleh dikongsi dengan pelanggan.
  4. Keselamatan akaun: aktifkan 2FA di Settings › Security.

📝 Nama menu boleh berbeza sedikit antara versi. Jika tidak jumpa, rujuk wiki rasmi.

Backup (penting)

Menurut wiki rasmi (panduan migrasi v1 → v2), backup folder data kini satu-satunya kaedah backup yang disokong — ciri backup/restore JSON lama telah dibuang.

Contoh mudah (hentikan dahulu supaya pangkalan data tidak sedang ditulis):

cd ~/uptime-kuma
sudo docker compose down
sudo tar czf ~/uptime-kuma-data-$(date +%F).tar.gz data
sudo docker compose up -d

Simpan fail .tar.gz itu di tempat lain (komputer anda, server lain atau storan awan). Jika anda pilih MariaDB luaran, backup pangkalan data itu juga secara berasingan.

Semak siapa guna port 3001:

sudo ss -tulpn | grep -E ':3001 '

📝 Arahan reset kata laluan rasmi ialah docker exec -it <nama bekas> bash kemudian npm run reset-password. Arahan docker compose exec di atas ialah bentuk setara untuk Docker Compose.

10. Seterusnya (pilihan)

HTTPS: jangan biarkan Uptime Kuma terbuka di HTTP biasa. Letak di belakang reverse proxy (contoh Nginx, Apache atau Caddy) dengan sijil TLS dan domain anda sendiri. Ikut contoh konfigurasi rasmi: Uptime Kuma Docs — Reverse Proxy. Perkara penting daripada docs tersebut:

  • Uptime Kuma berasaskan WebSocket — proksi mesti hantar header Upgrade dan Connection.
  • Sub-direktori tidak disokong (contoh contoh.com/uptimekuma). Guna domain atau subdomain sendiri, contoh https://status.contoh.com.
  • Jika Uptime Kuma hanya boleh dicapai melalui proksi, anda boleh set Settings › Reverse Proxy › Trust Proxy kepada Yes supaya IP pelanggan sebenar dipaparkan dalam log.

Kemas kini Uptime Kuma (ikut How to Update rasmi):

  1. Backup dahulu (Seksyen 8).
  2. Baca nota keluaran di https://github.com/louislam/uptime-kuma/releases.
  3. Tarik imej baharu dan cipta semula bekas:
cd ~/uptime-kuma
sudo docker compose pull
sudo docker compose up -d --force-recreate

📝 Docs rasmi menyatakan imej Docker untuk setiap keluaran baharu mengambil sedikit masa untuk dibina — jika belum tersedia, cuba lagi kemudian.

⚠️ Naik taraf daripada Uptime Kuma 1.x? Versi 2 ialah kemas kini major dengan breaking changes, dan migrasi pangkalan data boleh ambil masa lama (sehingga berjam-jam pada data besar). Backup folder data, baca Migration From v1 To v2 dahulu, dan jangan ganggu proses migrasi.

Keselamatan asas: kemas kini Ubuntu secara berkala (sudo apt upgrade), guna kunci SSH (bukan kata laluan), dan semak storan kosong dengan df -h.
