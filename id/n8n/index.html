Cara install n8n pakai Docker Compose

1. Apa itu n8n?

n8n adalah tool otomatisasi workflow — mirip Zapier/Make, tetapi bisa Anda host sendiri. Anda menghubungkan aplikasi (Google Sheets, Telegram, WhatsApp API, LLM, webhook) dan membangun otomatisasi secara visual.

Cocok untuk: pemilik UMKM, freelancer, dan tim IT kecil yang ingin otomatisasi tanpa biaya per-task.

  • Repo resmi: https://github.com/n8n-io/n8n
  • Dokumentasi resmi: https://docs.n8n.io/hosting/installation/server-setups/docker-compose/

💡 Jujur dulu: n8n sendiri menyebutkan self-hosting cocok untuk pengguna yang terbiasa mengelola server. Kalau Anda tidak mau repot mengurus server, backup, dan keamanan, n8n Cloud adalah pilihan yang lebih mudah: https://n8n.io/pricing/

2. Prasyarat

  • VPS dengan Ubuntu 24.04 atau 22.04 (64-bit) dan akses sudo.
  • Domain atau subdomain (contoh n8n.contoh.com) — dibutuhkan untuk HTTPS otomatis. Belum punya domain? Lihat Opsi tanpa domain.
  • Dasar SSH: bisa login dengan ssh user@IP_SERVER.
  • Email untuk sertifikat SSL Let's Encrypt.
  • Port 80 dan 443 terbuka di firewall penyedia VPS.

4. Install Docker

Login ke VPS, lalu perbarui sistem:

sudo apt update && sudo apt upgrade -y

Install Docker Engine + plugin Docker Compose dengan skrip resmi Docker:

curl -fsSL https://get.docker.com -o get-docker.sh
sudo sh get-docker.sh

Ingin cara manual (repo apt)? Ikuti panduan resmi: https://docs.docker.com/engine/install/ubuntu/

Cek instalasi:

docker --version
docker compose version
sudo docker run hello-world

Jika muncul pesan Hello from Docker!, Docker sudah siap.

(Opsional) Pakai Docker tanpa sudo:

sudo usermod -aG docker ${USER}
exec sg docker newgrp
groups   # pastikan "docker" ada di daftar

5. Install n8n

5.1 Atur DNS

Di panel domain Anda, tambahkan record A:

Tipe Nama Tujuan
A n8n (atau subdomain pilihan) IP_SERVER_ANDA

Tunggu beberapa menit. Cek dengan ping n8n.contoh.com — hasilnya harus menunjukkan IP server Anda.

5.2 Buka firewall (ufw)

sudo ufw allow OpenSSH
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw enable
sudo ufw status

⚠️ Izinkan OpenSSH dulu sebelum ufw enable, kalau tidak Anda bisa terkunci dari server.

5.3 Buat folder proyek dan file .env

mkdir n8n-compose
cd n8n-compose
nano .env

Tempel lalu ganti nilainya sesuai data Anda:

# Domain utama
DOMAIN_NAME=contoh.com

# Subdomain — n8n akan bisa diakses di https://n8n.contoh.com
SUBDOMAIN=n8n

# Zona waktu untuk node Schedule/Cron (WITA: Asia/Makassar, WIT: Asia/Jayapura)
GENERIC_TIMEZONE=Asia/Jakarta

# Email untuk sertifikat TLS/SSL (Let's Encrypt)
SSL_EMAIL=anda@contoh.com

Simpan (Ctrl+O, Enter, Ctrl+X), lalu kunci izin file:

chmod 600 .env

5.4 Buat folder file lokal

Folder ini dibagi antara n8n dan server (misalnya untuk node Read/Write Files from Disk):

mkdir local-files

5.5 Buat file compose.yaml

nano compose.yaml

Tempel isi berikut (sama dengan contoh resmi n8n):

services:
  traefik:
    image: "traefik"
    restart: always
    command:
      - "--api.insecure=true"
      - "--providers.docker=true"
      - "--providers.docker.exposedbydefault=false"
      - "--entrypoints.web.address=:80"
      - "--entrypoints.web.http.redirections.entryPoint.to=websecure"
      - "--entrypoints.web.http.redirections.entrypoint.scheme=https"
      - "--entrypoints.websecure.address=:443"
      - "--certificatesresolvers.mytlschallenge.acme.tlschallenge=true"
      - "--certificatesresolvers.mytlschallenge.acme.email=${SSL_EMAIL}"
      - "--certificatesresolvers.mytlschallenge.acme.storage=/letsencrypt/acme.json"
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - traefik_data:/letsencrypt
      - /var/run/docker.sock:/var/run/docker.sock:ro

  n8n:
    image: n8nio/n8n
    restart: always
    ports:
      - "127.0.0.1:5678:5678"
    labels:
      - traefik.enable=true
      - traefik.http.routers.n8n.rule=Host(`${SUBDOMAIN}.${DOMAIN_NAME}`)
      - traefik.http.routers.n8n.tls=true
      - traefik.http.routers.n8n.entrypoints=web,websecure
      - traefik.http.routers.n8n.tls.certresolver=mytlschallenge
      - traefik.http.middlewares.n8n.headers.SSLRedirect=true
      - traefik.http.middlewares.n8n.headers.STSSeconds=315360000
      - traefik.http.middlewares.n8n.headers.browserXSSFilter=true
      - traefik.http.middlewares.n8n.headers.contentTypeNosniff=true
      - traefik.http.middlewares.n8n.headers.forceSTSHeader=true
      - traefik.http.middlewares.n8n.headers.SSLHost=${DOMAIN_NAME}
      - traefik.http.middlewares.n8n.headers.STSIncludeSubdomains=true
      - traefik.http.middlewares.n8n.headers.STSPreload=true
      - traefik.http.routers.n8n.middlewares=n8n@docker
    environment:
      - N8N_ENFORCE_SETTINGS_FILE_PERMISSIONS=true
      - N8N_HOST=${SUBDOMAIN}.${DOMAIN_NAME}
      - N8N_PORT=5678
      - N8N_PROTOCOL=https
      - NODE_ENV=production
      - N8N_WEBHOOK_URL=https://${SUBDOMAIN}.${DOMAIN_NAME}/
      - GENERIC_TIMEZONE=${GENERIC_TIMEZONE}
      - TZ=${GENERIC_TIMEZONE}
      - N8N_RESTRICT_FILE_ACCESS_TO=/files
    volumes:
      - n8n_data:/home/node/.n8n
      - ./local-files:/files

volumes:
  n8n_data:
  traefik_data:

Fungsi file ini (singkat):

  • traefik — "penjaga pintu". Menerima trafik di port 80/443, mengambil sertifikat HTTPS gratis secara otomatis, lalu meneruskannya ke n8n.
  • n8n — aplikasi n8n. Port 5678 hanya dibuka di 127.0.0.1 (di dalam server saja), jadi akses dari luar harus lewat HTTPS melalui Traefik.
  • n8n_data — menyimpan database SQLite dan kunci enkripsi (encryption key) n8n. Jangan dihapus!
  • traefik_data — menyimpan sertifikat SSL.
  • ./local-files → /files — folder bersama. Di n8n, gunakan path /files.

📝 N8N_WEBHOOK_URL tersedia mulai n8n 2.30.0. Jika Anda memakai versi lebih lama, ganti dengan WEBHOOK_URL.

5.6 Jalankan n8n

sudo docker compose up -d

Untuk menghentikan:

sudo docker compose stop

6. Catatan .env

Variabel Fungsi Nilai aman / contoh
DOMAIN_NAME Domain utama Anda contoh.com
SUBDOMAIN Subdomain untuk n8n n8n → https://n8n.contoh.com
GENERIC_TIMEZONE Zona waktu node jadwal (default New York jika kosong) Asia/Jakarta
SSL_EMAIL Email notifikasi sertifikat Let's Encrypt email yang aktif Anda baca

Aturan keamanan:

  • Jangan commit .env ke GitHub. Tambahkan .env ke .gitignore.
  • chmod 600 .env supaya hanya pemilik yang bisa membaca.
  • API key/token yang Anda masukkan ke n8n disimpan sebagai credentials yang dienkripsi dengan kunci di volume n8n_data. Backup volume itu — tanpa kunci, credentials tidak bisa dibuka.
  • Jika token bocor, segera ganti (rotate) di penyedia aslinya.
  • Tidak ada password default: Anda membuat akun pemilik (owner) sendiri saat pertama kali membuka n8n — pakai password yang kuat.

7. Verifikasi

sudo docker compose ps

Seharusnya ada dua service (traefik dan n8n) dengan status running / Up.

Lihat log jika perlu:

sudo docker compose logs -f n8n
sudo docker compose logs -f traefik

Buka browser: https://n8n.contoh.com (sesuai domain Anda).

✅ Tampilan yang diharapkan: halaman n8n untuk membuat akun pemilik (owner account) — isi email, nama, dan password. Setelah itu Anda masuk ke editor workflow.

n8n hanya bisa diakses lewat HTTPS, bukan HTTP biasa.

Opsi tanpa domain (tunnel SSH)

Belum punya domain? Anda bisa mencoba n8n secara pribadi tanpa membuka port publik:

# Di VPS:
sudo docker volume create n8n_data
sudo docker run -d --name n8n --restart unless-stopped \
  -p 127.0.0.1:5678:5678 \
  -e GENERIC_TIMEZONE="Asia/Jakarta" -e TZ="Asia/Jakarta" \
  -e N8N_ENFORCE_SETTINGS_FILE_PERMISSIONS=true \
  -v n8n_data:/home/node/.n8n \
  n8nio/n8n

# Di komputer Anda (terminal baru):
ssh -L 5678:localhost:5678 user@IP_SERVER

Lalu buka http://localhost:5678 di komputer Anda. Webhook dari luar tidak akan berfungsi di mode ini — hanya untuk belajar/uji coba.

8. Error umum

Gejala Penyebab umum Solusi
bind: address already in use (port 80/443) Apache/Nginx sudah berjalan Cek port (perintah di bawah tabel) → hentikan service itu (sudo systemctl disable --now apache2 atau nginx)
permission denied ... /var/run/docker.sock User bukan anggota grup docker Pakai sudo, atau jalankan langkah usermod di Bagian 4 lalu login ulang
Browser menampilkan peringatan sertifikat / sertifikat tidak terbit DNS belum menyebar, atau port 80/443 diblokir Cek record A, ufw status, dan firewall di panel VPS. Lihat sudo docker compose logs traefik untuk error ACME
n8n restart terus / Killed / lambat RAM kurang (OOM) Tambah swap (di bawah) atau upgrade ke RAM 2 GB
EACCES: permission denied pada /files Pemilik folder local-files salah sudo chown -R 1000:1000 local-files (n8n berjalan sebagai UID 1000)
URL webhook menampilkan localhost:5678 Variabel webhook belum diatur Pastikan N8N_WEBHOOK_URL (≥2.30.0) atau WEBHOOK_URL (versi lama) benar, lalu docker compose up -d
docker-compose: command not found Memakai perintah lama (v1) Gunakan docker compose (pakai spasi, plugin v2)
Peringatan secure cookie saat membuka http://IP:5678 n8n mengharapkan HTTPS Pakai domain + HTTPS, atau tunnel SSH ke localhost

Cek siapa yang memakai port 80/443:

sudo ss -tulpn | grep -E ':(80|443) '

Tambah swap 2 GB (untuk VPS 1 GB):

sudo fallocate -l 2G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
free -h

9. Selanjutnya (opsional)

Update n8n:

cd ~/n8n-compose
sudo docker compose pull
sudo docker compose down
sudo docker compose up -d

💡 Ingin lebih terkontrol? Kunci versi, misalnya image: n8nio/n8n:2.45.7, lalu naikkan versi secara manual setelah membaca catatan rilis. n8n merilis versi minor hampir setiap minggu; gunakan versi stable untuk produksi.

Backup volume data:

sudo docker volume ls     # cari nama volume, biasanya n8n-compose_n8n_data
sudo docker run --rm \
  -v n8n-compose_n8n_data:/data \
  -v "$(pwd)":/backup \
  alpine tar czf /backup/n8n_data-$(date +%F).tar.gz -C /data .

Simpan file backup di luar VPS (misalnya di komputer Anda atau cloud storage).

Ekspor workflow (tambahan):

sudo docker compose exec n8n n8n export:workflow --all --output=/files/workflows-backup.json

File akan muncul di folder local-files/.

Keamanan dasar: update Ubuntu secara berkala (sudo apt upgrade), gunakan SSH key (bukan password), dan jangan membuka port 5678 langsung ke internet.
