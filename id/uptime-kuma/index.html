Cara install Uptime Kuma pakai Docker Compose

1. Apa itu Uptime Kuma?

Uptime Kuma adalah tool monitoring uptime self-hosted — alternatif layanan seperti UptimeRobot yang berjalan di server Anda sendiri. Tool ini mengecek website, API, dan server Anda secara berkala, lalu mengirim notifikasi (misalnya Telegram, Discord, Slack, email) saat ada yang tidak bisa diakses.

Beberapa fitur yang tercantum di README resmi:

  • Monitor HTTP(s), TCP, keyword HTTP(s), JSON Query, WebSocket, Ping, record DNS, Push, container Docker, dan lainnya
  • Notifikasi via Telegram, Discord, Gotify, Slack, Pushover, email (SMTP), dan 90+ layanan lain
  • Interval pengecekan hingga 20 detik
  • Beberapa status page sekaligus (bisa dipetakan ke domain sendiri), info sertifikat SSL, dukungan 2FA

Cocok untuk: pemilik website, freelancer, dan tim kecil yang ingin tahu lebih dulu saat website atau layanannya down — tanpa langganan bulanan.

  • Repo resmi: https://github.com/louislam/uptime-kuma
  • Dokumentasi resmi: https://uptime.kuma.pet/docs/How-to-Install/

💡 Tips penting: Agar monitoring bermakna, pasang Uptime Kuma di server yang berbeda dari website/layanan yang dipantau. Jika keduanya di VPS yang sama dan VPS itu down, Uptime Kuma ikut down — dan tidak ada yang mengirim notifikasi.

2. Prasyarat

  • VPS dengan Ubuntu 24.04 atau 22.04 (64-bit) dan akses sudo.
  • Docker Engine dengan plugin Docker Compose — perintahnya docker compose, bukan docker-compose (di-install di Bagian 4).
  • Disk lokal untuk folder data. Dokumentasi resmi menyatakan filesystem jaringan seperti NFS tidak didukung (lihat Bagian 6).
  • Tool curl dan dasar SSH: bisa login ssh user@IP_SERVER.
  • Port 3001 dibuka di firewall penyedia VPS — atau pakai tunnel SSH (lihat Akses pribadi pakai tunnel SSH), yang lebih aman.

4. Install Docker

Login ke VPS, lalu perbarui sistem:

sudo apt update && sudo apt upgrade -y

Install Docker Engine + plugin Docker Compose memakai skrip resmi Docker:

curl -fsSL https://get.docker.com -o get-docker.sh
sudo sh get-docker.sh

Ingin cara manual (repo apt)? Ikuti panduan resmi: https://docs.docker.com/engine/install/ubuntu/

Cek instalasi:

docker --version
docker compose version
sudo docker run hello-world

Jika muncul pesan Hello from Docker! dan docker compose version menampilkan nomor versi, Docker sudah siap.

(Opsional) Pakai Docker tanpa sudo:

sudo usermod -aG docker ${USER}
exec sg docker newgrp
groups   # pastikan "docker" ada di daftar

5. Install Uptime Kuma

5.1 Buat folder proyek dan unduh compose.yaml

Perintah resmi dari README Uptime Kuma:

mkdir uptime-kuma
cd uptime-kuma
curl -o compose.yaml https://raw.githubusercontent.com/louislam/uptime-kuma/master/compose.yaml

Cek isi file:

cat compose.yaml

Isi resmi (saat panduan ini ditulis, 3 Nov 2026):

services:
  uptime-kuma:
    image: louislam/uptime-kuma:2
    restart: unless-stopped
    volumes:
      - ./data:/app/data
    ports:
      # <Host Port>:<Container Port>
      - "3001:3001"

Arti setiap baris (singkat):

  • image: louislam/uptime-kuma:2 — tag :2 selalu mengikuti rilis versi major 2 terbaru. Saat panduan ini ditulis, rilis terbaru adalah 2.5.9 (dirilis 31 Okt 2026).
  • ./data:/app/data — semua data (database, pengaturan, monitor) disimpan di folder data di samping compose.yaml. Jangan hapus folder ini.
  • "3001:3001" — antarmuka web di port 3001.

5.2 Jalankan Uptime Kuma

sudo docker compose up -d

Setelah image selesai diunduh, Uptime Kuma berjalan di semua antarmuka jaringan — misalnya http://IP_SERVER:3001.

Untuk menghentikan: sudo docker compose down (data di ./data tetap aman).

6. Catatan penyimpanan dan keamanan

⚠️ NFS / filesystem jaringan tidak didukung. Dokumentasi resmi menyatakan filesystem harus mendukung POSIX file lock agar database SQLite tidak rusak. Petakan /app/data ke folder lokal atau Docker volume — bukan NFS, SMB, atau penyimpanan jaringan lainnya.

Aturan keamanan:

  • http://IP_SERVER:3001 adalah HTTP biasa (tidak terenkripsi). Membuka port 3001 ke internet tanpa HTTPS berisiko — password admin dan data monitor dikirim tanpa enkripsi. Pakai tunnel SSH untuk mulai, dan siapkan reverse proxy + HTTPS sebelum diakses dari internet (lihat Bagian 10).
  • Port yang dipublikasikan Docker biasanya melewati aturan ufw. Jangan menganggap ufw saja sudah melindungi port 3001 — cek juga firewall di panel VPS.
  • Aktifkan 2FA untuk akun admin setelah login (Settings › Security).

7. Verifikasi dan buat akun admin

sudo docker compose ps

✅ Container uptime-kuma seharusnya berstatus Up. Image resmi punya healthcheck bawaan, jadi statusnya bisa berubah menjadi healthy setelah beberapa menit.

Lihat log jika container terus restart:

sudo docker compose logs -f uptime-kuma

Buka browser ke:

http://IP_SERVER:3001

✅ Layar yang diharapkan (pertama kali):

  1. Pilih database — Uptime Kuma 2 bertanya "Which database would you like to use?". Untuk setup kecil, pilih SQLite (antarmukanya menyebut recommended for small-scale deployments). Pilihan lain: Embedded MariaDB (sudah ada di image Docker) atau MariaDB/MySQL eksternal.
  2. Buat akun admin — isi username dan password yang kuat.

⚠️ Buat akun admin segera setelah Uptime Kuma berjalan. Selama belum ada admin, siapa pun yang bisa mengakses port 3001 bisa menyiapkannya lebih dulu. Tunnel SSH (di bawah) menghindari risiko ini.

Akses pribadi pakai tunnel SSH

README resmi menunjukkan cara membatasi akses hanya ke localhost dengan -p 127.0.0.1:3001:3001 (contoh docker run). Untuk Docker Compose, ubah baris port di compose.yaml dengan cara yang sama (tips kami, diadaptasi dari contoh resmi):

    ports:
      - "127.0.0.1:3001:3001"

Lalu jalankan ulang:

sudo docker compose down
sudo docker compose up -d

Dari komputer Anda (terminal baru):

ssh -L 3001:localhost:3001 user@IP_SERVER

Buka http://localhost:3001 di komputer Anda. Hanya Anda (melalui SSH) yang bisa mengakses Uptime Kuma. Pengaturan ini juga cocok jika Anda memasang reverse proxy di VPS yang sama.

8. Setelah install

  1. Tambah monitor pertama: klik Add New Monitor, pilih jenis (misalnya HTTP(s)), isi nama dan URL website Anda, lalu Save.
  2. Siapkan notifikasi: Settings › Notifications › Setup Notification, pilih layanan (misalnya Telegram atau email SMTP) dan klik Test untuk memastikan pesan terkirim. Lalu aktifkan notifikasi tersebut di monitor Anda.
  3. (Opsional) Status page: Status Pages › New Status Page untuk halaman status publik yang bisa dibagikan ke pelanggan.
  4. Keamanan akun: aktifkan 2FA di Settings › Security.

📝 Nama menu bisa sedikit berbeda antarversi. Jika tidak ketemu, lihat wiki resmi.

Backup (penting)

Menurut wiki resmi (panduan migrasi v1 → v2), backup folder data saat ini satu-satunya metode backup yang didukung — fitur backup/restore JSON lama sudah dihapus.

Contoh sederhana (hentikan dulu agar database tidak sedang ditulis):

cd ~/uptime-kuma
sudo docker compose down
sudo tar czf ~/uptime-kuma-data-$(date +%F).tar.gz data
sudo docker compose up -d

Simpan file .tar.gz tersebut di tempat lain (komputer Anda, server lain, atau cloud storage). Jika Anda memilih MariaDB eksternal, backup juga database tersebut secara terpisah.

9. Error umum

Gejala Penyebab umum Solusi
Tidak bisa membuka http://IP_SERVER:3001 Port belum dibuka di firewall VPS, atau port diikat ke 127.0.0.1 Buka port 3001 di panel VPS, atau pakai tunnel SSH
bind: address already in use (port 3001) Layanan lain memakai port 3001 Ganti port host, misalnya "3002:3001", lalu buka http://IP_SERVER:3002
Error database is locked / database rusak Folder data di NFS atau penyimpanan jaringan Pindahkan data ke disk lokal atau Docker volume (Bagian 6)
Dashboard macet / tidak update di belakang reverse proxy Header WebSocket Upgrade dan Connection tidak diteruskan Ikuti Reverse Proxy resmi (Bagian 10)
Monitor localhost selalu DOWN Di dalam container Docker, localhost merujuk ke container itu sendiri Lihat Troubleshooting resmi untuk jaringan Docker
Lupa password admin — Ikuti Reset Password via CLI: sudo docker compose exec uptime-kuma npm run reset-password
permission denied ... /var/run/docker.sock Pengguna bukan anggota grup docker Pakai sudo, atau jalankan langkah usermod di Bagian 4 lalu login ulang

Cek siapa yang memakai port 3001:

sudo ss -tulpn | grep -E ':3001 '

📝 Perintah reset password resmi adalah docker exec -it <nama container> bash lalu npm run reset-password. Perintah docker compose exec di atas adalah bentuk setaranya untuk Docker Compose.

10. Selanjutnya (opsional)

HTTPS: jangan biarkan Uptime Kuma terbuka di HTTP biasa. Pasang di belakang reverse proxy (misalnya Nginx, Apache, atau Caddy) dengan sertifikat TLS dan domain Anda sendiri. Ikuti contoh konfigurasi resmi: Uptime Kuma Docs — Reverse Proxy. Poin penting dari dokumentasi tersebut:

  • Uptime Kuma berbasis WebSocket — proxy harus meneruskan header Upgrade dan Connection.
  • Subdirektori tidak didukung (misalnya contoh.com/uptimekuma). Pakai domain atau subdomain sendiri, misalnya https://status.contoh.com.
  • Jika Uptime Kuma hanya bisa diakses lewat proxy, Anda bisa mengatur Settings › Reverse Proxy › Trust Proxy ke Yes agar IP klien yang sebenarnya tampil di log.

Update Uptime Kuma (ikuti How to Update resmi):

  1. Backup dulu (Bagian 8).
  2. Baca catatan rilis di https://github.com/louislam/uptime-kuma/releases.
  3. Tarik image baru dan buat ulang container:
cd ~/uptime-kuma
sudo docker compose pull
sudo docker compose up -d --force-recreate

📝 Dokumentasi resmi menyebutkan image Docker untuk setiap rilis baru butuh waktu untuk dibuild — jika belum tersedia, coba lagi nanti.

⚠️ Upgrade dari Uptime Kuma 1.x? Versi 2 adalah update major dengan breaking changes, dan migrasi database bisa memakan waktu lama (hingga berjam-jam untuk data besar). Backup folder data, baca Migration From v1 To v2 lebih dulu, dan jangan hentikan proses migrasi.

Keamanan dasar: perbarui Ubuntu secara berkala (sudo apt upgrade), pakai kunci SSH (bukan password), dan pantau sisa ruang disk dengan df -h.

Pertanyaan umum (FAQ)

Database mana yang sebaiknya dipilih pertama kali?

Untuk setup kecil, pilih SQLite — antarmuka Uptime Kuma sendiri menyarankannya untuk deployment skala kecil. Embedded MariaDB atau MariaDB/MySQL eksternal juga didukung.

Bisakah folder data disimpan di NFS atau network storage?

Tidak. Sistem file harus mendukung POSIX file lock; NFS/SMB bisa menyebabkan error database is locked atau database rusak. Pakai disk lokal atau Docker volume (Bagian 6).

Saya lupa password admin. Apa yang harus dilakukan?

Jalankan sudo docker compose exec uptime-kuma npm run reset-password di folder proyek, seperti di Error umum.

Kenapa monitor localhost selalu DOWN?

Di dalam container Docker, localhost merujuk ke container itu sendiri, bukan server Anda. Lihat Troubleshooting resmi untuk jaringan Docker.
