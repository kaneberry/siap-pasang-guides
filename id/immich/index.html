Cara install Immich pakai Docker Compose

1. Apa itu Immich?

Immich adalah aplikasi foto dan video self-hosted — alternatif Google Photos atau iCloud Photos yang berjalan di server Anda sendiri. Aplikasi mobile (Android/iOS) bisa mencadangkan foto secara otomatis ke server, dan antarmuka web memungkinkan Anda melihat timeline, album, peta, berbagi album, serta mencari foto berdasarkan wajah atau isi foto (machine learning berjalan di server Anda).

Cocok untuk: keluarga atau perorangan yang ingin menyimpan foto sendiri tanpa bergantung pada penyimpanan cloud berbayar, dan siapa pun yang ingin kendali penuh atas data pribadinya.

  • Repo resmi: https://github.com/immich-app/immich
  • Dokumentasi resmi: https://docs.immich.app/install/docker-compose

💡 Jujur dulu: Immich lebih berat dibanding kebanyakan tool self-hosted — minimum resminya RAM 6 GB. Faktor terbesar justru penyimpanan: library foto Anda akan terus membesar setiap tahun, dan thumbnail serta video hasil transcode menambah sekitar 10–20% lagi. Immich bukan pengganti backup — Anda tetap perlu salinan di tempat lain (lihat Bagian 8).

2. Prasyarat

  • VPS dengan Ubuntu 24.04 atau 22.04 (64-bit) dan akses sudo. Dokumentasi resmi menyarankan Linux; Windows/macOS tidak disarankan untuk server.
  • Minimum resmi: RAM 6 GB, CPU 2 core (disarankan 8 GB dan 4 core).
  • CPU amd64 atau arm64. Untuk amd64, container machine learning Immich v3 butuh level x86-64-v2 (kebanyakan CPU sejak ~2012).
  • Docker Engine dengan plugin Docker Compose — perintahnya docker compose, bukan docker-compose (di-install di Bagian 4).
  • Penyimpanan yang cukup untuk semua foto/video Anda, dengan filesystem Unix (misalnya EXT4). Database harus di disk lokal (lebih baik SSD).
  • Tool wget dan dasar SSH: bisa login ssh user@IP_SERVER.
  • Port 2283 dibuka di firewall penyedia VPS — atau pakai tunnel SSH (lihat Akses pribadi pakai tunnel SSH), yang lebih aman.

3. 📦 Ukuran VPS disarankan

📦 Ukuran VPS disarankan untuk Immich

RAM vCPU Disk
Lebih nyaman (rekomendasi resmi) 8 GB 4 100 GB+ (sesuai ukuran library)
Minimum (resmi) 6 GB 2 40 GB+

RAM dan vCPU diambil dari persyaratan resmi Immich (minimum 6 GB / 2 core, disarankan 8 GB / 4 core). Ukuran disk adalah rekomendasi kami: hitung total ukuran foto dan video Anda, tambah 10–20% untuk thumbnail dan transcode, plus beberapa GB untuk database (biasanya 1–3 GB) dan sistem. Untuk library besar, pertimbangkan block storage tambahan untuk UPLOAD_LOCATION — tetapi tetap simpan database di disk lokal.

Pilihan penyedia (tautan resmi): Vultr · DigitalOcean · Hostinger VPS

Harga bisa berubah — cek harga terbaru di situs resmi. Atau pakai VPS apa saja / PC sendiri.

ℹ️ Pengungkapan: Tautan di kotak ini akan menjadi tautan afiliasi apabila tautan afiliasi diaktifkan; kami mungkin mendapat komisi tanpa biaya tambahan bagi Anda. Saat ini semua tautan adalah tautan resmi biasa. Baca pengungkapan lengkap.

4. Install Docker

Login ke VPS, lalu perbarui sistem:

sudo apt update && sudo apt upgrade -y

Install Docker Engine + plugin Docker Compose memakai skrip resmi Docker:

curl -fsSL https://get.docker.com -o get-docker.sh
sudo sh get-docker.sh

Ingin cara manual (repo apt)? Ikuti panduan resmi: https://docs.docker.com/engine/install/ubuntu/

⚠️ Jangan pakai paket docker.io atau docker-compose dari repo Ubuntu. Dokumentasi resmi Immich menyebut paket ini menyebabkan error seperti unknown shorthand flag: 'd' in -d. Pakai Docker Engine resmi seperti di atas.

Cek instalasi:

docker --version
docker compose version
sudo docker run hello-world

Jika muncul pesan Hello from Docker! dan docker compose version menampilkan nomor versi, Docker sudah siap.

(Opsional) Pakai Docker tanpa sudo:

sudo usermod -aG docker ${USER}
exec sg docker newgrp
groups   # pastikan "docker" ada di daftar

5. Install Immich

5.1 Buat folder proyek

mkdir ./immich-app
cd ./immich-app

Semua file Immich (docker-compose.yml, .env, dan secara default folder foto serta database) akan berada di folder ini.

5.2 Unduh docker-compose.yml dan .env

Perintah resmi ini mengunduh file dari rilis terbaru Immich di GitHub:

wget -O docker-compose.yml https://github.com/immich-app/immich/releases/latest/download/docker-compose.yml
wget -O .env https://github.com/immich-app/immich/releases/latest/download/example.env

Saat panduan ini ditulis (2 Nov 2026), rilis terbaru adalah v3.3.5 (diterbitkan 21 Okt 2026).

📝 Mengunduh lewat browser? Pastikan Anda mengganti nama example.env menjadi .env.

5.3 Isi file .env

Buat password database acak (huruf dan angka saja):

openssl rand -hex 24

Salin output-nya, lalu buka .env:

nano .env

Ubah baris-baris berikut:

# Lokasi foto/video yang di-upload — harus punya ruang disk yang cukup
UPLOAD_LOCATION=./library

# Lokasi file database — disk lokal saja (BUKAN network share)
DB_DATA_LOCATION=./postgres

# Hapus tanda # dan atur zona waktu Anda (WIB; WITA = Asia/Makassar, WIT = Asia/Jayapura)
TZ=Asia/Jakarta

# Versi Immich (v3 = selalu ikut rilis v3 terbaru)
IMMICH_VERSION=v3

# Ganti dari "postgres" ke output openssl tadi (A-Za-z0-9 saja)
DB_PASSWORD=tempel-output-openssl-di-sini

Simpan (Ctrl+O, Enter, Ctrl+X), lalu kunci izin file:

chmod 600 .env

📌 IMMICH_VERSION: nilai default v3 mengikuti rilis v3 terbaru setiap kali Anda menarik image. Ingin kendali penuh? Kunci ke versi tertentu, misalnya IMMICH_VERSION=v3.3.5 — tetapi Anda harus memperbarui nilai ini sendiri setiap kali upgrade.

5.4 Jalankan Immich

sudo docker compose up -d

Unduhan pertama butuh beberapa menit. Empat container akan dijalankan:

  • immich_server — aplikasi web dan API (port 2283)
  • immich_machine_learning — pencarian pintar dan pengenalan wajah
  • immich_postgres — database
  • immich_redis — antrean tugas (image Valkey)

Yang perlu diketahui (singkat):

  • Foto Anda ada di folder UPLOAD_LOCATION (default ./library), database di DB_DATA_LOCATION (default ./postgres). Jangan hapus kedua folder ini.
  • Untuk menghentikan semua container: sudo docker compose down (data tetap aman).

6. Catatan .env dan keamanan

Variabel Fungsi Nilai aman / contoh
UPLOAD_LOCATION Folder foto/video, thumbnail, dan backup database otomatis ./library atau disk besar, misalnya /mnt/foto
DB_DATA_LOCATION Folder file Postgres ./postgres — disk lokal (SSD), bukan NFS/SMB
DB_PASSWORD Password Postgres Output openssl rand -hex 24 (A-Za-z0-9 saja)
TZ Zona waktu server Asia/Jakarta
IMMICH_VERSION Tag image Immich v3 atau versi tetap, misalnya v3.3.5

Aturan keamanan:

  • Jangan commit .env ke GitHub. chmod 600 .env agar hanya pemilik yang bisa membaca.
  • Postgres tidak dibuka ke internet di docker-compose.yml resmi — jangan tambahkan port database atau Redis.
  • http://IP_SERVER:2283 adalah HTTP biasa (tidak terenkripsi). Membuka port 2283 ke internet tanpa HTTPS berisiko — password dan foto pribadi dikirim tanpa enkripsi. Pakai tunnel SSH untuk awal, dan siapkan HTTPS sebelum memakai aplikasi mobile dari luar rumah (lihat Bagian 10).
  • Port yang dipublikasikan Docker biasanya melewati aturan ufw. Jangan anggap ufw saja sudah melindungi port 2283 — cek juga firewall di panel VPS.

7. Verifikasi dan buat akun admin

sudo docker compose ps

✅ Keempat container seharusnya berstatus Up — immich_server akan berubah menjadi healthy setelah beberapa saat.

Lihat log jika ada container yang restart terus:

sudo docker compose logs -f immich-server
sudo docker compose logs -f immich-machine-learning

Buka browser ke:

http://IP_SERVER:2283

✅ Tampilan yang diharapkan: halaman sambutan Immich. Klik Getting Started dan ikuti petunjuk untuk mendaftar. Pengguna pertama yang mendaftar menjadi admin.

⚠️ Daftarkan akun admin segera setelah Immich berjalan. Selama belum ada admin, siapa pun yang bisa menjangkau server Anda bisa mendaftar lebih dulu dan menjadi admin. Tunnel SSH (di bawah) menghindari risiko ini.

Akses pribadi pakai tunnel SSH

Tidak ingin membuka port 2283 ke internet? Di docker-compose.yml, pada layanan immich-server, ubah baris port:

    ports:
      - '127.0.0.1:2283:2283'

Lalu jalankan ulang:

sudo docker compose down
sudo docker compose up -d

Dari komputer Anda (terminal baru):

ssh -L 2283:localhost:2283 user@IP_SERVER

Buka http://localhost:2283 di komputer Anda. Hanya Anda (lewat SSH) yang bisa mengakses Immich.

📝 Cara mengikat ke 127.0.0.1 ini adalah tips kami (format port standar Docker Compose), bukan langkah di dokumentasi resmi Immich. Aplikasi mobile tidak bisa memakai tunnel ini dari luar — untuk itu, siapkan HTTPS (Bagian 10). Ingat untuk mengulang perubahan ini jika Anda mengunduh docker-compose.yml baru.

8. Setelah install

Ringkasan langkah dari Immich Docs — Post Installation:

  1. Pengguna lain (opsional): Administration › Users › Create user untuk anggota keluarga.
  2. Storage template (opsional): Administration › Settings › Storage Template menentukan susunan folder file di disk (default: Tahun/Tahun-Bulan-Hari/NamaFile). Atur sejak awal sebelum meng-upload banyak foto.
  3. Aplikasi mobile: unduh Immich di Google Play, App Store, F-Droid, atau GitHub Releases. Login dengan URL server, misalnya http://IP_SERVER:2283 (atau URL HTTPS Anda).
  4. Backup foto dari ponsel: di aplikasi, ketuk ikon awan, pilih album, lalu Enable Backup.

Backup server (wajib)

Dokumentasi resmi menekankan strategi 3-2-1: minimal tiga salinan, di dua jenis media, dengan satu salinan di lokasi lain.

  • Immich membuat backup database secara otomatis ke UPLOAD_LOCATION/backups (default: setiap hari pukul 02.00, menyimpan 14 salinan terakhir). Pengaturannya di Administration › Settings › Database Dump Settings.
  • Backup database tidak berisi foto/video — hanya metadata. Anda harus mem-backup seluruh folder UPLOAD_LOCATION ke tempat lain (disk lain, server lain, atau cloud storage) memakai tool backup Anda sendiri.
  • Ikuti panduan resmi untuk detail dan cara restore: Immich Docs — Backup and Restore.

Cek siapa yang memakai port 2283:

sudo ss -tulpn | grep -E ':2283 '

10. Selanjutnya (opsional)

HTTPS: jangan biarkan Immich terbuka di HTTP biasa, terutama jika aplikasi mobile akan mencadangkan foto dari luar rumah. Pasang Immich di belakang reverse proxy (misalnya Nginx, Caddy, atau Traefik) dengan sertifikat TLS dan domain Anda sendiri. Ikuti persyaratan resmi: Immich Docs — Reverse Proxy. Poin penting dari dokumentasi tersebut:

  • Immich harus disajikan di root (sub)domain, misalnya https://foto.contoh.com — bukan sub-path seperti /immich.
  • Proxy harus meneruskan header Host, X-Real-IP, X-Forwarded-Proto, X-Forwarded-For dan mengizinkan upload file besar.

Ubah pengaturan: edit .env, lalu:

sudo docker compose up -d

Update Immich (ikuti Immich Docs — Upgrading):

  1. Baca catatan rilis di https://github.com/immich-app/immich/releases — terutama bagian breaking changes.
  2. Backup dulu (Bagian 8).
  3. Untuk upgrade versi major, update aplikasi mobile lebih dulu — server hanya kompatibel dengan aplikasi versi major yang sama.
  4. Jika Anda mengunci versi, ubah IMMICH_VERSION di .env (misalnya v3.3.5 → versi tujuan).
  5. Tarik image baru dan jalankan ulang:
cd ~/immich-app
sudo docker compose pull && sudo docker compose up -d
  1. (Opsional) Bersihkan image lama: sudo docker image prune

⚠️ Downgrade tidak didukung oleh Immich, bahkan dalam versi minor yang sama. Karena itu backup sebelum update sangat penting. Jika catatan rilis meminta docker-compose.yml baru, unduh ulang dan terapkan lagi perubahan Anda — jangan timpa file .env Anda.

Keamanan dasar: perbarui Ubuntu secara berkala (sudo apt upgrade), pakai kunci SSH (bukan password), dan pantau sisa ruang disk dengan df -h sebelum disk penuh.

11. ⚠️ Penafian

Panduan tidak resmi. Tidak berafiliasi dengan Immich, FUTO, atau penyedia VPS mana pun. Nama/logo milik pemiliknya masing-masing. Gunakan dengan risiko Anda sendiri dan selalu cek dokumentasi resmi. Penafian lengkap.

Pertanyaan umum (FAQ)

Berapa RAM yang dibutuhkan Immich?

Minimal 6 GB RAM, dan 8 GB disarankan (lihat Bagian 3). RAM yang kurang bisa membuat container restart terus atau upload sangat lambat.

Bisakah database Immich disimpan di NFS atau network share?

Tidak. Taruh DB_DATA_LOCATION di disk lokal dengan sistem file Unix (misalnya EXT4). Network share atau NTFS/FAT bisa merusak database Postgres.

Apakah backup database otomatis sudah cukup?

Tidak. Backup otomatis hanya berisi metadata, bukan foto/video. Anda perlu mem-backup seluruh folder UPLOAD_LOCATION ke tempat lain — lihat Backup server (wajib).

Kenapa aplikasi mobile tidak bisa terhubung?

Cek URL lengkap, termasuk :2283 dan http atau https yang benar. Untuk backup dari luar rumah, siapkan HTTPS lewat reverse proxy (Bagian 10).
