Cara install Dify pakai Docker Compose

1. Apa itu Dify?

Dify adalah platform untuk membangun aplikasi AI — chatbot, workflow/chatflow, agen AI, dan basis pengetahuan (RAG) — lewat antarmuka visual. Anda menghubungkan model dari penyedia seperti OpenAI, Anthropic, Gemini, atau Ollama, lalu menerbitkan aplikasinya sebagai web app atau API.

Cocok untuk: tim kecil dan UMKM yang ingin membuat chatbot internal atau otomatisasi AI berbasis dokumen sendiri, serta developer yang ingin membuat prototipe aplikasi AI dengan cepat.

  • Repo resmi: https://github.com/langgenius/dify
  • Dokumentasi resmi: https://docs.dify.ai/en/self-host/deploy/quick-start/docker-compose

💡 Jujur dulu: Dify jauh lebih berat dibanding n8n atau Open WebUI. Satu instalasi menjalankan lebih dari 15 container (API, worker, database, Redis, database vektor, sandbox, dan lainnya). Dify juga tidak punya model sendiri — Anda butuh API key penyedia model atau Ollama. Kalau tidak ingin repot mengurus server, Dify Cloud adalah pilihan yang lebih mudah: https://dify.ai/pricing

2. Prasyarat

  • VPS dengan Ubuntu 24.04 atau 22.04 (64-bit) dan akses sudo.
  • Minimum resmi: CPU ≥ 2 core, RAM ≥ 4 GiB.
  • Docker 19.03+ dan Docker Compose 2.24.0+ (di-install di Bagian 4).
  • Tool git, curl, dan jq (di-install di Bagian 5.1).
  • Dasar SSH: bisa login ssh user@IP_SERVER.
  • API key penyedia model (misalnya OpenAI) atau Ollama yang bisa dijangkau dari server.
  • Port 80 dibuka di firewall penyedia VPS — atau pakai tunnel SSH (lihat Akses pribadi pakai tunnel SSH), yang lebih aman.

4. Install Docker

Login ke VPS, lalu perbarui sistem:

sudo apt update && sudo apt upgrade -y

Install Docker Engine + plugin Docker Compose memakai skrip resmi Docker:

curl -fsSL https://get.docker.com -o get-docker.sh
sudo sh get-docker.sh

Ingin cara manual (repo apt)? Ikuti panduan resmi: https://docs.docker.com/engine/install/ubuntu/

Cek instalasi:

docker --version
docker compose version
sudo docker run hello-world

Pastikan docker compose version menunjukkan 2.24.0 atau lebih baru — Dify tidak akan jalan dengan versi lebih lama. Jika muncul pesan Hello from Docker!, Docker sudah siap.

(Opsional) Pakai Docker tanpa sudo:

sudo usermod -aG docker ${USER}
exec sg docker newgrp
groups   # pastikan "docker" ada di daftar

5. Install Dify

5.1 Install git, curl, dan jq

sudo apt install -y git curl jq

5.2 Unduh (clone) Dify versi terbaru

Perintah resmi ini mencari tag rilis terbaru lewat API GitHub, lalu meng-clone versi tersebut:

git clone --branch "$(curl -s https://api.github.com/repos/langgenius/dify/releases/latest | jq -r .tag_name)" https://github.com/langgenius/dify.git

Ingin tahu dulu versi apa yang akan di-install?

curl -s https://api.github.com/repos/langgenius/dify/releases/latest | jq -r .tag_name

Saat panduan ini ditulis (2 Nov 2026), hasilnya adalah 1.18.0.

📝 Error fatal: Remote branch null not found? Biasanya karena API GitHub membatasi permintaan tanpa login, sehingga jq mengembalikan null. Clone dengan tag yang ditulis langsung — cek nomor versi terbaru di https://github.com/langgenius/dify/releases:

bash git clone --branch 1.18.0 https://github.com/langgenius/dify.git

5.3 Siapkan file .env

cd dify/docker
cp .env.example .env

Semua pengaturan awal yang penting ada di docker/.env.

5.4 Buat token sandbox agen (wajib)

openssl rand -base64 32

Salin hasilnya, lalu buka .env:

nano .env

Cari baris DIFY_AGENT_LOCAL_SANDBOX_AUTH_TOKEN= (pakai Ctrl+W untuk mencari) dan tempel hasil tadi:

DIFY_AGENT_LOCAL_SANDBOX_AUTH_TOKEN=tempel-hasil-openssl-di-sini

Simpan (Ctrl+O, Enter, Ctrl+X), lalu kunci izin file:

chmod 600 .env

⚠️ Menurut dokumentasi resmi, layanan agent_backend dan sandbox-nya tidak akan berjalan tanpa token ini.

5.5 Jalankan Dify

sudo docker compose up -d

Unduhan pertama butuh beberapa menit (banyak image). Container yang dijalankan:

  • 7 layanan inti: api, api_websocket, worker, worker_beat, web, plugin_daemon, agent_backend
  • 8 komponen pendukung: weaviate (database vektor), db_postgres, redis, nginx, ssrf_proxy, agent_ssrf_proxy, sandbox, local_sandbox
  • 1 tugas sekali jalan: init_permissions — mengatur izin storage, lalu berhenti

Yang perlu diketahui (singkat):

  • nginx adalah pintu masuk tunggal — mendengarkan di port 80 server Anda dan meneruskan trafik ke web dan api.
  • Data (database, file unggahan, vektor) disimpan di folder dify/docker/volumes/. Jangan hapus folder ini.
  • Untuk menghentikan semua container: sudo docker compose down (data tetap aman).

6. Catatan .env dan keamanan

Variabel Fungsi Nilai aman / contoh
DIFY_AGENT_LOCAL_SANDBOX_AUTH_TOKEN Token antara agen dan sandbox lokal (wajib) Hasil openssl rand -base64 32
SECRET_KEY Kunci penanda tangan sesi Biarkan kosong — Dify membuat kunci permanen otomatis di folder storage
EXPOSE_NGINX_PORT Port HTTP di server 80 (default). Ganti jika port 80 sudah terpakai
EXPOSE_NGINX_SSL_PORT Port HTTPS di server 443 (default)

Aturan keamanan:

  • Jangan commit .env ke GitHub. chmod 600 .env supaya hanya pemilik yang bisa membaca.
  • Di .env.example versi 1.18.0, DIFY_AGENT_SERVER_SECRET_KEY berisi nilai default untuk development dan komentar di file itu meminta nilainya diganti untuk production. Ikuti petunjuk di komentar tersebut.
  • API key penyedia model yang Anda masukkan ke Dify disimpan di database (di dalam volumes/). Backup folder itu dan lindungi. Kalau API key bocor, ganti (rotate) di penyedia aslinya secepatnya.
  • http://IP_SERVER adalah HTTP biasa (tidak terenkripsi). Membuka port 80 ke internet tanpa HTTPS berisiko — password dan API key dikirim tanpa enkripsi. Pakai tunnel SSH untuk awal, dan siapkan HTTPS sebelum dibagikan ke orang lain (lihat Bagian 9).
  • Port yang dipublikasikan Docker biasanya melewati aturan ufw. Jangan anggap ufw saja sudah melindungi port 80 — cek juga firewall di panel VPS.

7. Verifikasi dan buat akun admin

sudo docker compose ps

✅ Setiap container seharusnya berstatus Up atau healthy. Status Exited untuk init_permissions itu normal (tugas sekali jalan).

Lihat log jika ada container yang restart terus:

sudo docker compose logs -f api
sudo docker compose logs -f agent_backend

Buka browser ke halaman inisialisasi admin:

http://IP_SERVER/install

✅ Tampilan yang diharapkan: formulir untuk menyiapkan akun admin (email, nama, password). Setelah selesai, login di http://IP_SERVER.

⚠️ Selesaikan langkah /install segera setelah Dify berjalan. Selama akun admin belum dibuat, siapa pun yang bisa menjangkau server Anda bisa membukanya lebih dulu. Tunnel SSH (di bawah) menghindari risiko ini.

Langkah berikutnya di Dify: buka Settings › Model Provider, install plugin penyedia model Anda, lalu masukkan API key.

Akses pribadi pakai tunnel SSH

Tidak ingin membuka port 80 ke internet? Di docker/.env, ikat port nginx ke 127.0.0.1 saja:

EXPOSE_NGINX_PORT=127.0.0.1:80
EXPOSE_NGINX_SSL_PORT=127.0.0.1:443

Lalu jalankan ulang:

sudo docker compose down
sudo docker compose up -d

Dari komputer Anda (terminal baru):

ssh -L 8080:localhost:80 user@IP_SERVER

Buka http://localhost:8080/install di komputer Anda. Hanya Anda (lewat SSH) yang bisa mengakses Dify.

📝 Cara mengikat ke 127.0.0.1 ini adalah tips kami (format port standar Docker Compose), bukan langkah di dokumentasi resmi Dify. Jika ada fitur yang tidak berfungsi lewat tunnel, kembalikan nilai awal dan pakai HTTPS.

9. Selanjutnya (opsional)

HTTPS: jangan biarkan Dify terbuka di HTTP biasa untuk dipakai tim. Dua pilihan:

  • Taruh Dify di belakang reverse proxy Anda sendiri (misalnya Caddy/Traefik/Nginx) dengan sertifikat TLS, atau
  • Pakai dukungan HTTPS bawaan nginx Dify — variabel NGINX_HTTPS_ENABLED, NGINX_SSL_CERT_FILENAME, serta bagian Certbot Configuration (CERTBOT_EMAIL, CERTBOT_DOMAIN). Ikuti dokumentasi resmi: Dify Docs — Environment Variables.

Setelah HTTPS aktif, perbarui variabel URL (misalnya CONSOLE_API_URL, CONSOLE_WEB_URL) agar memakai https://.

Ubah pengaturan: edit docker/.env, lalu:

sudo docker compose down
sudo docker compose up -d

Backup sebelum update (wajib):

cd ~/dify/docker && sudo docker compose down
cd ~ && sudo cp -r dify "dify.bak.$(date +%Y%m%d%H%M%S)"

Perintah cp adalah saran dokumentasi resmi (FAQ). Kami menghentikan container dulu agar salinan database konsisten. Simpan juga salinan backup di luar VPS.

Update Dify:

  • Langkah upgrade bisa berbeda antar versi. Baca catatan rilis versi tujuan di https://github.com/langgenius/dify/releases dan ikuti petunjuknya.
  • Setelah upgrade, bandingkan .env.example baru dengan .env Anda untuk variabel baru atau yang berubah:
cd ~/dify/docker
diff .env.example .env
  • Jika Anda pernah mengubah docker-compose.yaml, terapkan ulang perubahan Anda ke file baru — jangan pertahankan file lama, karena versi baru bisa menambah layanan yang dibutuhkan Dify.
  • Lalu tarik image baru dan jalankan ulang:
sudo docker compose pull
sudo docker compose up -d

Keamanan dasar: perbarui Ubuntu secara berkala (sudo apt upgrade), pakai kunci SSH (bukan password), dan jangan buka port database atau Redis ke internet.
